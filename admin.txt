ADMIN WORKFLOW – FINAL DESIGN
1. Role & Responsibility of Admin (High-Level)

The Admin acts as:
    System Supervisor

    Policy Interpreter

    Final Authority in Disputes

    Audit & Compliance Controller

    Admin does not replace Accountant and does not block Faculty–Accountant direct flow, but:

    Oversees the entire process

    Steps in only when something goes wrong

2. Admin Access Scope

    Admin has read access to everything and write access only where supervision is required.

    Admin can:

    View all claims (draft / submitted / approved / rejected / paid)

    Reject claims (with reason)

    Send claims back for correction

    View faculty + external examiner details

    View accountant actions

    View calculation breakdowns

    View audit logs

    Resolve queries

    Admin cannot:

    Create claims

    Edit claim financial values

    Approve payments

    Change calculated amounts manually

3. Admin Dashboard
    Purpose

    Provide a system-wide snapshot of ERMS health.

    Dashboard Components
    3.1 System Summary Cards

    Total claims generated

    Submitted claims

    Approved by accountant

    Paid claims

    Rejected claims

    External examiner claims

    3.2 Alerts / Flags

    Claims pending beyond time limit

    Claims with repeated rejections

    Claims edited after draft multiple times

    External claims without documents

    Rate mismatches / minimum applied flags

    3.3 Quick Filters

    By department

    By exam type

    By academic year

    By status

    By faculty / external

4. Claim Supervision Workflow
    4.1 Normal Flow (No Admin Involvement)
    Faculty → Submit Claim
    ↓
    Accountant → Verify → Approve → Pay


    Admin only monitors.

    4.2 Admin Intervention Flow (When Needed)

    Admin steps in when:

    Accountant rejects a claim

    Faculty raises a dispute

    Policy ambiguity exists

    External examiner claim mismatch

    Rule violation detected

    Faculty / Accountant → Raises issue
            ↓
    Admin → Reviews claim + rules
            ↓
    Admin Action:
    • Reject with reason
    • Send back for correction
    • Allow override (rare, logged)

5. Claim Rejection & Correction Flow (Admin)
    5.1 Reject Claim

    Admin can reject a claim at any stage before payment.

    Mandatory fields:

    Rejection reason

    Reference to rule / policy

    Optional remarks

    System effect:

    Claim status → rejected

    Claim locked from payment

    Faculty notified

    5.2 Send Back for Correction

    Admin can:

    Change status → draft

    Add correction instructions

    Faculty can:

    Edit only allowed fields

    Re-submit

    All edits are audit logged.

6. External Examiner Supervision

Admin oversees the external examiner flow, which includes:

6.1 External Link Monitoring

Who generated the link

Which exam it belongs to

Expiry status

Whether used or not

6.2 Document Verification

Admin can view:

PAN upload

ID proof

Travel documents

Signed claim PDFs

Admin does not approve payment, but can:

Flag missing/invalid documents

Block claim until corrected

7. Faculty & Accountant Oversight
7.1 Faculty Profile View

Admin can view:

Faculty personal info

Bank details (read-only)

Total claims history

Rejected claim history

External claims generated by faculty

7.2 Accountant Action Audit

Admin can view:

Which accountant approved which claim

Time taken for approval

Payment reference numbers

Status changes history

8. Query & Dispute Resolution

Admin is the final resolver for queries.

Query Sources:

Faculty → “Why rejected?”

Accountant → “Policy unclear”

System → “Rule mismatch detected”

Admin Actions:

Reply to query

Attach clarification

Change claim status if required

Close query

9. Audit & Compliance
9.1 Audit Logs (Critical)

Admin can view:

Claim creation

Draft edits

Submissions

Rejections

Overrides

Payments

Audit logs are:

Immutable

Timestamped

User-linked

10. Admin Settings & Controls
Admin can configure:

Exam rate masters (if updated by college)

Batch size rules

Staff norms tables

Academic year locking

Claim submission deadline windows

These are configuration-level actions, not per-claim edits.

11. Security & Locking Rules
Action	Admin Allowed
Edit draft claim	❌
Change calculated amount	❌
Reject claim	✅
Force correction	✅
View all data	✅
Approve payment	❌
12. Final Admin Philosophy

Admin is not a processor.
Admin is not an approver.
Admin is the system’s conscience.

Ensures fairness

Enforces policy

Resolves ambiguity

Protects institution integrity

✅ Resulting System Balance
Role	Primary Function
Faculty	Create & submit claims
Accountant	Verify, approve, pay
Admin	Supervise, interpret, resolve
